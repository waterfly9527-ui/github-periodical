本周判断

未来团队可能更换模型和客户端，却保留自己的技能库、记忆格式、验证规则和治理流程。可移植层正在成为比单一 Agent 产品更长期的资产。

六层项目版图

以下分层为编辑部基于 GitHub 仓库能力做出的归纳，并非 GitHub 官方分类。

1. 工程方法Superpowers：规格、TDD、审查与交付。
2. 轻量技能Skills：小型、可修改的工程技能文件。
3. 学习与记忆Hermes：从经验生成技能与用户模型。
4. 治理与上下文ECC：规则、Hooks、安全与共享记忆。
5. 可替换客户端OpenCode：权限和交互运行容器。
6. 个人 Agent 环境OpenClaw：长期在线、插件化助手。

团队采用路径

  1. 先把需求澄清、TDD、审查写成技能。
  2. 再统一项目决策、术语和交接的记忆格式。
  3. 区分只读规划、可写开发和高风险工具调用。
  4. 最后验证同一技能在两个客户端上的行为差异。

主要风险

  • 技能供应链和脚本风险。
  • 错误记忆长期污染。
  • 不同客户端行为不一致。
  • 流程过载降低小任务效率。
  • 个人 Agent 扩大隐私暴露面。
