三层项目版图

不要把这些项目当作同一类数据库互相替换；它们解决的是不同层的问题。

01 · CRDT 核心

Automerge · Yjs

处理离线并发修改、冲突自由合并、增量同步协议与共享数据类型。

02 · 客户端数据库

RxDB · LiveStore · Jazz

把持久化、响应式查询、schema、事件或关系数据模型与同步变成应用的一等数据层。

03 · 服务器同步桥

Electric · PowerSync

从 Postgres/中心数据库把部分数据同步到客户端本地读写模型，减少应用自己实现复制协议。

团队采用路径

以下是编辑建议，不是仓库官方推荐。

已有 Postgres Web 应用

Postgres → Electric → 客户端本地集合。先把 local-first 限制在 read-path，改造半径最小。

React Native / 离线移动端

中心数据库 → PowerSync → SQLite → UI。优先验证长时间断网、上传队列和重连。

纯 JS 多平台产品

RxDB + 固定 storage/replication adapter。适合希望保留后端自由度的团队。

事件可追溯状态

LiveStore → event log → SQLite materializer → sync backend。先验证 schema 演进和回放成本。

富文本 / 白板 / IDE

Yjs 或 Automerge + 自选 provider/persistence。数据模型首先按“共享文档”而不是“关系表”设计。

愿意试新一体化方案

Jazz 2.0 alpha 小范围试点。适合原型与非核心模块，不宜忽略 API 变动风险。

四个需要提前验证的风险

权限不是同步自动解决的

离线副本、撤权、附件访问和服务端过滤必须单独建模。

Schema 演进比 Demo 更难

长离线设备可能跨多个版本重新上线，迁移、删除语义和兼容窗口必须测试。

CRDT ≠ 通用数据库

CRDT 很适合共享对象，但全局索引、复杂查询和服务端分析通常仍需要另一层。

必须做故障注入

重复消息、乱序、网络抖动、超长离线期、大数据量和设备时钟异常都应进入测试矩阵。
