Agent 正在接管软件交付闭环：从理解系统到验证上线

AI 编程工具的分水岭，正在从“能不能写出代码”转向“能不能理解已有系统、遵循工程流程、操作真实界面，并拿出可复核的交付证据”。本期沿着软件生产链路，拆解 8 个值得放进技术雷达的开源项目。

本期判断：Agent 的能力边界不再只由模型决定，而由它能否接入可靠的工具、受控的执行环境、真实的测试反馈和独立验证机制共同决定。

先看技术链路

这 8 个仓库不是一套已经集成好的产品，而是软件交付闭环中的不同组件；团队需要按权限和质量要求组合。

趋势判断：代码生成正在成为中间步骤。真正决定 Agent 是否能进入生产工作流的，是前后两端：前端要有足够的系统上下文，后端要有可复核的测试、安全与发布证据。没有这两端，Agent 只是更快地产生待人工检查的代码。
01 · 理解REA / Craft Anything：观察已有软件、提取行为与界面线索。
02 · 规划Agent Skills：把需求拆成规格、原子任务和验收条件。
03 · 执行T3 Code：管理本机多个编码 Agent 的会话与入口。
04 · 构建与操作Astryx / agent-browser：约束 UI 组件，并在真实浏览器中验证交互。
05 · 安全验收Cloudflare Audit / Codex Security：形成覆盖记录、漏洞证据与修复复核。

推荐采用顺序

先用 Agent Skills 固化需求、计划和测试要求，让 Agent 先给出可审查计划。
把本地 Agent 放进独立 worktree 或容器，再接入 T3 Code 控制会话。
用 REA / Craft Anything 获取系统证据；区分观察事实与模型推断。
用 Astryx 约束 UI，用 agent-browser 检查真实页面和交互结果。
最后接入安全审计；漏洞修复、依赖升级和部署保留人工批准点。

采用前必须看清的边界

Skill 是指令与脚本，不是安全沙箱。权限隔离要由操作系统、容器、凭证和宿主工具实现。
浏览器和远程 Agent 控制可能触发真实副作用；使用隔离账号、测试环境和操作确认。
逆向分析与 clean-room 重建必须基于授权，并检查版权、商标、隐私和服务条款。
自动安全审计有覆盖盲区和误报；保留源码证据、扫描范围和未验证事项。
Astryx 处于 Beta，Craft Anything 处于 early alpha；生产采用前先做兼容性和稳定性验证。
本期项目属于不同层次，不能直接拼成“全自动交付”；每个连接点都需要权限、测试和人工责任人。

编辑结论

Agent 工程化的下一阶段，不是把所有工具交给一个更大的 Agent，而是把软件开发拆成可观察、可授权、可回滚、可验证的步骤。值得优先投入的不是“全自动按钮”，而是系统上下文、可重复流程、真实验收和安全证据这四类基础设施。
