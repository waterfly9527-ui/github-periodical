GitHub 仓库事实

本期 6 个仓库分别覆盖模型漏洞扫描（garak）、红队与评估编排（Promptfoo、PyRIT）、Agent/MCP/Skill 资产扫描（Agent Scan）、全栈 AI 红队（AI-Infra-Guard）以及攻击/防御基准（AgentDojo）。其中 Agent Scan、AI-Infra-Guard、Promptfoo、PyRIT 在 2026-09-15 至 09-16 仍有 GitHub push；Agent Scan、AI-Infra-Guard、Promptfoo、garak 在 09-09 至 09-10 有新 Release。

编辑分析

Agent 安全的工程重心正在从“模型会不会被 jailbreak”扩展到“Agent 能发现什么工具、拥有什么权限、执行什么动作、数据如何跨工具流动”。团队需要分层建设：模型基线扫描 → Agent/MCP/Skill 资产盘点 → CI 红队门禁 → 运行前权限与执行边界 → 基准回归，而不是依赖单一扫描器。

风险与边界

  • 不要把“扫描通过”等同于 Agent 安全：运行时权限、凭证、网络出口和人工审批仍需独立控制。
  • Agent Scan README 明确提示：扫描 stdio MCP 配置会执行配置中的命令；评估不可信 MCP 时应放入隔离环境。
  • 规则型扫描会遇到误报/漏报；AI-Infra-Guard 近期专门合并降低 Skill Scan 误报的修复，说明证据与复核机制仍重要。
  • 不同工具覆盖层级不同：garak 偏模型，Agent Scan 偏组件发现，Promptfoo/PyRIT 偏红队编排，不能用 Stars 简化为同类排名。
  • AgentDojo 的近期活跃度明显低于其余项目；作为基准可参考，但生产采用前应检查维护节奏与兼容性。

团队采用路径

  1. 第 1 周：用 garak 建立模型安全基线，同时列出当前 Agent 的工具、MCP servers、skills、凭证和网络出口。
  2. 第 2 周：在隔离环境运行 Agent Scan 或 AI-Infra-Guard，对 MCP/Skill 做资产发现与静态/动态扫描，先处理高危执行与凭证问题。
  3. 第 3 周：把 Promptfoo 或 PyRIT 的关键攻击场景固化为 CI 回归；每个已修复漏洞至少保留一个失败用例。
  4. 上线前：对高风险工具设置最小权限、参数约束、网络 egress 和人工审批；扫描结果只作为证据之一。
  5. 持续阶段：用 AgentDojo 或内部基准集做防御回归，分别记录攻击成功率、误报、阻断成本和业务可用性。
